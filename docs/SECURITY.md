# Security

## Obligation binding

Earlier releases (hardened-v6 through v8) bound an evidence artifact to a rail only through publisher identity, authority, version, and the observation window — not to *which obligation* the rail is actually about. A correctly signed, correctly hashed, schema-valid artifact concerning an unrelated obligation could in principle satisfy the quorum for a rail it was never meant to settle, since `name` and `criterion` are free text the contract never inspects.

`hardened-v9` introduced this (retired; hardened-v10 is a fresh redeploy of the identical mechanism): the policy now carries a frozen `obligation_id` (a canonical string the issuer commits at `open_rail`, part of the immutable policy), and every retrieved artifact must carry the identical `obligation_id` or the contract classifies it `INVALID` and the source does not count toward quorum (`tests/direct/test_proofrail_direct.py::test_evidence_for_a_different_obligation_is_rejected_even_when_correctly_hashed`). This stops reuse of authentic-but-unrelated evidence. It does **not** verify that the `obligation_id` string itself accurately describes the real-world obligation in `criterion` — that correspondence is established off-chain by the issuer choosing the id and the publishers agreeing to measure against it, the same way the obligation itself is established off-chain. `criterion` remains human-readable context, not an input to classification.

## Evidence isolation and false classifications

Challenge prose and evidence prose never enter an instruction channel and cannot select a code. The uptime rule accepts only exact structured facts—total seconds, unavailable seconds, and matching period bounds—and applies frozen integer basis-point arithmetic. Publisher outcome codes remain visible assertions but are ignored. A false or confidently wrong model response has no execution path, while missing, ambiguous, malformed, or inconsistent facts fail closed as `INVALID` or leave the panel below quorum.

**Capability scope:** this classification is deterministic integer arithmetic over schema-bound numeric facts, not `gl.nondet.exec_prompt()`-based or other LLM semantic reasoning about whether an obligation was met in some broader sense. No model call sits on the path from evidence to outcome code. If a deployment wants genuinely semantic, language-grounded adjudication (e.g. "did the vendor substantially comply with the SLA's intent"), that is a different, unimplemented capability and must not be implied by this contract's current behavior.

**Authenticated ≠ true.** The contract proves that a byte sequence is genuinely the one the pinned publisher DID authorizes and genuinely unmodified since publication (SHA-256 + `did:web` binding). It cannot prove the *content* of that byte sequence reflects reality. If every source required for quorum independently chooses to publish the same false facts, the contract authenticates and classifies them exactly as it would true facts — this is demonstrated, not just claimed, in `tests/direct/test_proofrail_direct.py::test_coordinated_identical_false_facts_pass_quorum_by_design`. Reducing this risk is the job of [publisher authority governance](AUTHORITY_GOVERNANCE.md) (real, separately accountable operators who would have to actually collude) — it is not something SHA-256/DID binding can address, by construction.

## Dispute-evidence scope, disclosed up front

There is exactly one counterevidence panel per rail: the one the issuer froze into the policy at `open_rail` time, before anyone has funded, claimed, or disputed anything. `dispute()` byte-compares the submitted panel to that frozen one and rejects any difference (`test_dispute_cannot_replace_precommitted_counterevidence`). This is a deliberate anti-griefing design choice — it stops a challenger from fabricating an arbitrary panel on the spot — not an oversight, and it means a recipient or issuer who disagrees with the issuer-chosen counter-panel has no on-chain mechanism to substitute, extend, or supplement it with their own sources. Their only lever is to request review of the panel that already exists. The full policy, including `counterevidence`, is public and readable (`get_rail`) before anyone transacts, so a prospective participant can inspect this limitation before funding or claiming, not discover it mid-dispute. If a deployment needs permissionless, abuse-resistant appeal with challenger-submitted evidence, that requires a different, unimplemented mechanism — this one explicitly does not provide it.

## Funds and liveness

Funding and challenge bonds must be exact. A storage guard rejects every write callback while native transfers are active. Transfers are attempted before settlement, recovery, or accounting state is committed, while GenVM transaction atomicity provides the final rollback boundary. Retry count and spacing, response sizes, and review windows are finite; recovery closes every nonterminal flow. Terminal rails cannot settle twice, and receipt rounds are restricted to 1–5.

An unresolved dispute cannot be reviewed after its three-day deadline. Permissionless recovery preserves the last verified provisional verdict and returns the bond to the challenger. This is intentionally neutral: infrastructure unavailability does not transfer the bond to either opponent, while withdrawing evidence cannot erase or improve the already-supported provisional financial outcome.

## Client transaction integrity

The frontend requires an injected wallet, never embeds signing keys, and treats a submitted hash as pending rather than successful. Success requires majority consensus plus explicit GenVM execution evidence. Creation enforces the same minimum post-observation claim window as the contract; disputes require a nonempty written reason; and recovery is offered only for contract states whose deadline has actually expired. These checks improve operator safety but do not replace contract enforcement.

## Residual assumptions

TLS origin authentication depends on the public PKI and publisher domain control at retrieval time. SHA-256 precommitment detects mutation but does not prove a statement is factually correct. Independent-source quorum and authenticated counterevidence reduce, but cannot eliminate, correlated publisher failure. GenLayer consensus governs nondeterministic acceptance.

The contract's documented web-access surface provides HTTP status and response bytes, not a final-response URL or redirect chain. It consequently enforces the normalized configured request origin/path, HTTP 200, DID service binding, and exact-byte digest in GenVM, while `scripts/verify_publishers.mjs` separately rejects redirects and checks final URL equality for release verification. The latter is an external verification control, not an in-contract final-origin guarantee.

The current five publisher origins (`hardened-v10`) are a protocol demonstration spread across three distinct hosting providers/accounts (Vercel, Cloudflare Pages, GitHub Pages), all operated by the same party. Their distinct domains, DIDs, and authority IDs prove that the anti-duplication and corroboration machinery works, and the multi-provider spread removes the single-shared-account correlation earlier releases had, but neither is evidence of organizational independence. Production authority admission follows [Publisher authority governance](AUTHORITY_GOVERNANCE.md): non-self-issued W3C VC 2.0 organizational credentials, active status, stable legal-entity identity (preferably GLEIF vLEI), separate operator/infrastructure control, and conflict disclosure. The current fixtures are explicitly `DEMONSTRATION_ONLY` and cannot satisfy that policy.
